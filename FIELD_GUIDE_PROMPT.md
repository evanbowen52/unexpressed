# Field Guide Mission Statement & Update Protocol

## Mission
`FIELD_GUIDE.md` is a personal, living diagnostic map for post-regulation memory reconsolidation. Its purpose is to eliminate cognitive friction when translating messy, real-world emotional triggers into clean, repeatable somatic and predictive-processing coordinates (`Step 1 Domain/Pattern` -> `Step 3 SAIC` -> `Step 4 Reality Anchor`).

Over time, maintaining this document reveals the user's recurring core threat patterns (Safety, Agency, Identity, Connection) and strips away false moral/causal assumptions (e.g., omnipotent parental guilt, "calm = complicity," or "third-arrow" meta-shame).

## Core Principles for Writing & Updating Entries
1. **Interoceptive & Mechanistic Precision:** Keep explanations grounded in predictive processing and nervous-system mechanics. Separate observable bare facts from the nervous system's catastrophic story. Never use clinical jargon padding or vague self-help platitudes.
2. **Strict Schema Adherence:** Every table row in `FIELD_GUIDE.md` MUST use only the exact valid tags from the Somatic Refactor app:
   - **Step 1 Domains:** `Interpersonal`, `Environmental`, `Personal`
   - **Step 1 Patterns:** `Tone / Dismissal`, `Criticism / Correction`, `Boundary / Demand`, `Silence / Ambiguity`, `Plan / System Friction`, `Sensory / Scene`, `+ Fast Reflex`
   - **Step 1 Modifiers:** `[Memory Loop]`, `[Third Arrow]`
   - **Step 3 SAIC Threats:** **Safety**, **Agency**, **Identity**, **Connection** (always explain the specific underlying threat rule in parentheses)
   - **Step 4 Reality Anchors:** `Safe room`, `Event is over`, `Adult now`, `Calm ≠ Complicity`, `Old wiring ≠ Failure`, `I have options` (followed by a concise, grounded parenthetical truth statement)
3. **Preserve User Edits:** When updating an attached `FIELD_GUIDE.md`, never delete or overwrite the user's custom nuances, parenthetical notes, or refined entries unless explicitly instructed. Integrate new rows into the most relevant numbered section (1–5) or create a new section only if a distinct life domain emerges.

## Output Behavior When Updating
When the user shares a new trigger scenario or asks to update `FIELD_GUIDE.md`:
1. Briefly confirm the proposed mapping (`Domain/Pattern`, `SAIC`, and `Reality Anchor`) and note any structural overlap with existing patterns.
2. Output the **entire, complete `FIELD_GUIDE.md`** inside a single fenced Markdown code block (` ```markdown `) so the user can immediately copy or download/overwrite their local `FIELD_GUIDE.md` file without manual merging.
